# The 22 documentation pages have never been assessed as a whole

The site publishes 22 pages under `docs/src/content/docs/`: four guides, the principles page, eleven specification pages, six runtime reference pages, and one project page. Each was written as its subject settled. No pass has read them together against the runtime as it stands today, and no pass has asked what order a first-time reader needs them in.

The plan already carries a related gap: an unfamiliar author following the guides through creating, moving, running, and inspecting an assembly. No outside reader is scheduled. This finding is the inside half of that work.

## What the assessment covers

**Accuracy.** Every command, flag, path, exit code, and file name checked against the runtime under `bot/` and against the specification under `specification/`. Command names moved recently and the noun-command migration is still in flight, so drift is expected.

**Internal consistency.** The specification pages cross-link heavily. Several links point at a page rather than at the section that answers them. Vocabulary must match `sdlc/planning/vocabulary.md`.

**Reading order.** The sidebar in `docs/astro.config.mjs` has four groups. Start Here puts "Your First Assembly" before "Install and Use", which asks a reader to build before they can run. Specification and Reference are autogenerated from `sidebar.order` frontmatter, so their order is whatever each page claimed for itself.

**First-time reader need.** What a newcomer must know before the specification is comprehensible, and whether any page supplies it.

## What it produces

A findings list, one entry per problem, each naming the page and what is wrong, sorted so the corrections can be ticketed separately. Plus a proposed sidebar with the reasoning for the order.

No page is rewritten under this finding. The assessment comes first and its findings become their own tickets.
