# Splitting the nav: Format and Runtime

The site mixed a portable folder format with one program that runs it. The sidebar now separates them, and one page explains the seam. This note records what was decided and what can be overturned.

## The groups

Start, Format, Runtime, Guides, Principles, Project.

**Start** is the reading path: Your First Assembly, The format and the runtime, Authoring Assemblies, Operating runs. **Format** holds the generated specification pages. **Runtime** holds the `bot` reference pages. **Guides** holds The Worked Example. **Principles** and **Project** hold one page each.

## Decisions

**Every page appears in exactly one group.** The brief put Authoring Assemblies in Start and also said Guides holds Authoring; a live review then ruled that The Worked Example must not appear twice. Both cannot hold at once, so the single-entry rule won. Authoring Assemblies sits in Start, and The Worked Example moves off the Start path into Guides, where it is the one how-to that is not a Start step. `docs/scripts/navigation.test.mjs` enforces the rule: a page in two groups, or in none, fails the gate. Overturn by choosing a different one-group home for either page.

**The Worked Example left the Start path.** It teaches `review/`, and Start already teaches `reading-list` in Your First Assembly. Three unrelated assemblies in a row taught nothing. The seam page now sends the reader to `examples/vtriage` next, which is the assembly the home page's record comes from.

**The two corpus explorers sit inside Format.** They landed on main in a temporary Format group of their own while this branch was open, because the generator wipes and rewrites the specification directory on every build and an authored page cannot live there. They now follow the overview inside the one Format group; the pages stay in `docs/src/content/docs/format/`.

**Format is an explicit list, not an autogenerated directory.** The worked example is generated into the same directory but belongs under Guides, and `autogenerate` cannot exclude one page. The navigation test catches a generated page nobody listed.

**`bot check` is the seam.** The new page `/format-and-runtime/` names it: the command a reader runs on their own folder is the command the 143 conformance cases run against a runtime. It is under 700 words and links onward rather than restating.

**Three runtime pages were split out of existing text, not written fresh.** Resuming a run came out of `reference/invocation.md`, where it was the fifth heading on a page about starting runs. Trust boundary came from the repository README's trust section. Limits and cost came from the budget paragraph in the operating-runs guide. Each source now links to the new page instead of holding the text. `published-runtime-contracts.test.mjs` followed the resume contract to its new page.

## Generator changes

`docs/scripts/generate-specification.mjs` gained three things, all mechanical, none touching the source prose.

1. **Anchors per source document.** A page built from several sources now knows the anchor of each one, computed from its first heading the way Starlight slugs it.
2. **An "On this page" line** on the six concatenated chapters, generated from those headings. Running and Structure were not split — the runtime team owns that prose — so the intro line is how a reader finds the document they came for.
3. **Condensed overview tables.** The overview shipped six tables and thirty-four rows, every row a bare link to the top of a page holding several documents. Each table is now one line of anchored links to the exact document. Same destinations, no table chrome, and the anchors the fresh-eyes review asked for.

## Left open

The install recipe still lives on two pages, and the legacy inspection commands (`bot show`, `bot runs`) are still taught beside the noun commands. Both are step 1 of the information-architecture study's build order and belong to a content pass, not this one. The lever is `guides/install-and-use.md`.
