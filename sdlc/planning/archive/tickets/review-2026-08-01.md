## Original findings as recorded (spec divergences — spec authority)

- **A1 — success hook's rewrite faults the run; spec says re-check
  and re-hash** (record.md: "the `success` hook's rewrite excepted,
  which is re-checked and re-hashed"; hooks.md: "the next stage sees
  what `success` left there"). `gating.ts complete()` seals against
  the pre-hook hash → any output-rewriting success hook = exit 2.
  `gating.test.ts:226` pins the NEGATION ("…is a fault, never a
  seal"). The loop's question round is the same window. → ticket.
- **A2 — the executable chooser is validated, then silently replaced
  by a model call** (choose.md: "Write one, and it chooses… costs no
  model call"). graph.ts validates the form; `ChooseNode` carries no
  chooser; `runChoose` always runs an agent; the
  `via: "executable"` record arm is dead code; the agent's prompt
  for a body-less CHOOSE never even lists the alternatives. An
  entire spec mode unimplemented and green. → ticket.
- **A3 — subflow children inherit the parent invocation's rungs and
  the ROOT flow's options** (subflow.md: "It does not inherit the
  invocation… the child resolves its options from its own
  sentinels, the home, and the defaults"). `defaultGating` closes
  over the root `read`/`flow`; a child's own FLOW.md options are
  ignored; `--model` leaks into children. No test drives
  `defaultGating` for a child. → ticket.

## Confirmed real (correctness/robustness)

- **A6 — `runProcess` settles on `'exit'` + a 10 ms drain timer**;
  large gate output can truncate under load — and the capture is
  what the record claims the agent read. Fix: settle on `'close'`.
  Also: second `terminate()` leaks the first kill timer. → ticket
  (small, with A5/A8).
- **A5 — a signal-aborted gate is recorded `judged: true`**;
  runtime.md says "the record claims nothing judged it". → same
  ticket.
- **A7 — `bot prune --delete` will delete a RUNNING run** (count
  window is name-order only; never consults run_end). → same ticket.
- **A8 — `terminate()` memoization makes post-signal group cleanup a
  no-op** for groups tracked after activation; narrow today, API
  reads re-runnable and isn't. → same ticket (or comment).
- **A4 — abandoned-prompt edges**: (1) the tap detaches AFTER the
  terminal stage_end is appended — a late-settling abandoned prompt
  can append events after its stage_end; fix ordering. (2) an
  ignored abort leaves a ghost harness running against the shared
  $PWD until process exit, spend unrecorded — record the
  unreconciled-work fact or bound it. → ticket (subtle; Fable lane).
