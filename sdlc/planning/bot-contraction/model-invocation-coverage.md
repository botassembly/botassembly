# Model invocation coverage

This map records the production routes that can construct a model, select a model, and send a model operation. It names the shared resolver, the record boundary, and the current test evidence.

## Shared path

`bot/src/options.ts:39-51` defines the eight-rung resolution ladder, and `bot/src/options.ts:94-119` applies it through the shared `resolveNodeOptions` call used by preflight and execution. `bot/src/machinery.ts:41-53` performs provider/model lookup, including unique providerless selection and refusal for no match or multiple providers. `bot/src/machinery.ts:205-225` is the normal default-gating source edge into `AgentHarness`; it passes the selected model and reasoning level. `bot/src/turns.ts:35-53` is the prompt funnel, and `bot/src/pi-tap.ts:282-288` records the provider operation immediately before the provider request.

## Prompt and continuation funnel

`bot/src/gating.ts:241-264` sends initial work prompts and Pi tool continuations through `prompt`; `bot/src/turns.ts:35-53` repeats truncated responses with the same harness. `bot/src/gating.ts:124-147` sends chooser prompts and send-backs through the same session. Loop questions are exercised by `bot/tests/cli-loop-pins.test.ts:170-201` and `:258-283`; immediate chooser selection is exercised by `bot/tests/cli-rejected-choose.test.ts:143-208`, chooser send-back by `bot/tests/gating.test.ts:206-222`, and the signal path by `bot/tests/control-container-signal.test.ts:62-91`; truncation continuation is covered by `bot/tests/gating.test.ts:142-154` and hostile truncation by `bot/tests/hostile-gating.test.ts:343-355`; temporary-directory warning and process cleanup are covered by `bot/tests/tmp-warning.test.ts:11-30` and shared temporary cleanup by `bot/tests/flow-cleanup.test.ts:115-154`. A repeated prompt reuses the already constructed stage or chooser harness.

## Record boundary

`bot/src/record-events.ts:124-145` serializes the complete resolved option ladder on `stage_start.options`, including provider, model, reasoning, and source rung when those values exist. `bot/src/record-events.ts:221-248` serializes provider/model on `provider_start` and `turn`. `bot/src/record-events.ts:45-88` serializes root and child run identity, correlation, and runtime provenance but no model ladder. A child `run_start` precedes its runtime resolver by `bot/src/subflow-runtime.ts:250-275`; static child preflight is the earlier refusal boundary, and this map does not claim runtime resolution precedes the child record.

The record-shape contract is covered by executable field-ledger validation in `bot/tests/record-event-shape.test.ts:181-193`, wrong-type and additive-field validation in `:209-221`, and required-field validation in `:223-231`; the provider-operation pairing oracle is `bot/tests/provider-operation-story.test.ts:8-18`. The focused runtime cases add behavioral proof without changing record fields or timing.
