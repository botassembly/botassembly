# The local gate halves its wall time and worker footprint, and coverage moves out of it

`bot/vitest.config.ts` now caps vitest at `Math.max(2, Math.floor(availableParallelism() / 2))` workers, overridable by `BOT_TEST_WORKERS`. `bot/Makefile` gains a `coverage` target running `npm run test:coverage`; `test:` runs the uninstrumented `npm run test`, so `make check` no longer collects coverage. `.github/workflows/runtime.yml` sets `BOT_TEST_WORKERS: "4"` for the hosted four-core runner, keeping it uncapped, and runs `make -C bot coverage` as its own step after `make check`. `CONTRIBUTING.md` states that the primary agent runs `make -C bot coverage` before writing a completion record and the record cites it, and that one broad gate runs per repository at a time. Four Buffer deep-equality sites in `run-output.test.ts` and `verified-output.test.ts` convert to `Buffer.equals` plus a length assertion. Two duplicate test pairs merge: `run-request.test.ts`'s large-retained-request case into its real-run retrieval case, and `run-output.test.ts`'s byte-boundary case into its large-accepted-output case. `cli-worktree-lock.test.ts` converts five subprocess tests to direct `main()` calls through the boundary the file already imports. `sidebar.test.mjs` merges into `redirects.test.mjs` to share one Astro build. `sdlc/issues/2026-09-14-gate-cost-on-shared-machine.md`, the origin issue, is deleted.

Independent design review rejected the first draft over dropped D4 proofs, the completion step, the hosted runner, the Astro build, and dependency on 0286. The corrected draft was accepted. Independent code review rejected the first commit on three findings: a dropped "No run's name starts with absent." stderr fragment that no other file actually owned, two more megabyte-scale Buffer comparisons the first scan missed, and a parallelized form of the twentieth duplicate group (`cli-lazy-model-runtime.test.ts`) that narrowed rather than closed a read/write race on `home/assemblies` and raised peak load on the shared machine, against this ticket's own goal. All three were fixed: the fragment restored, both Buffer sites converted, and the parallel form reverted to sequential. The amended commit was accepted at `abae8db`, rebased onto `b2a83f5`.

The complete local gate ran spec, lint, and test rungs separately in the foreground on the landed commit: 214 files, 1,742 tests (down from 1,744; the two removed tests' assertions survive in the tests named above), all 143 conformance cases, and static checks passed. `make -C bot coverage` printed `coverage-summary: 124 production modules across four dimensions.`, matching the count an instrumented run printed on main before this ticket; `make check` ran no instrumentation. The ratchet held at 18,874 nonblank lines. Hosted runtime run `34866423402` and hosted docs run `34866424028` both passed on commit `b2a83f5`; the runtime job's `make check` and `make -C bot coverage` steps both passed as separate steps.

Two limits stay open. The before-and-after timing (146.81 s wall / 726.68 s CPU at load 6.18, before; 84.44 s / 429.03 s at load 11.73, after) was measured against the parallel form of the twentieth duplicate group and was not retaken after code review reverted that group to sequential; the reverted form runs more `node` children serially than the measured "after" run did, so the true saving is smaller than the recorded 42% wall-time drop. Both measured runs, and the reconfirmation polling around them, ran on a shared machine whose one-minute load average never fell below 1.0 (it ran from 1.72 to 2.68 during a ten-minute poll before the runs, and sat at 6.18 and 11.73 for the runs themselves), so neither the recorded numbers nor this record's own coverage-summary and gate-count re-runs prove an idle-machine figure.

**Decision Ian can overturn:** coverage instrumentation moved out of `make check` into a separate `make coverage` target, run by the hosted check job and by the primary agent before a completion record, rather than divided across gates or left in place.
