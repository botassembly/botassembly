# Provider reports no longer echo a credential this run supplied

A value redactor now runs over the recognized credential environment names before a provider's report reaches a person. It reads `process.env` at redaction time, the same live environment ADR 0030 already treats as an authentication input, and replaces each occurrence of a recognized name's nonempty value with a marker naming that variable. It applies at four provider-facing sites: the 0283 refusal sentence before its 2,048-byte bound, the retry-settled and no-retry-context stream messages, and the `provider_transport` diagnostic. The registry in `credential-environment.ts` is split into 42 secret-bearing names that are redacted and 10 non-secret names, such as an account, a project, a region, an identifier, and a credential path, that are only scrubbed from child environments. An ordinary word like `default` is never marked as a redacted credential. The AWS container credentials relative URI is classified secret-bearing because reading it returns live credentials, not a stable identifier. `slots.md` now publishes and pins both lists. A new test asserts the retained Pi session file itself holds the redacted sentence, not the value. `bot/tests/synthetic-credential.ts` gives every fixture one shared synthetic credential constant instead of each inventing its own. `record.md` states the limit next to the fault sentence: matching is by value over the secret-bearing names, misses a credential Pi reads from `auth.json` or `models.json`, and cannot prove a report holds no secret. The origin issue file is deleted, its evidence carried forward into the ticket.

Independent design review rejected the first draft: it overclaimed the outcome, missed the fourth path at `pi-tap.ts`, left the value seam unnamed, and said nothing about Pi session files. The corrected draft was accepted. Independent code review found non-secret names were being redacted, rewriting ordinary words like `default` as if they were credentials, and two lows: no assertion that the retained session file was scrubbed, and four fixtures each planting a different synthetic value instead of sharing one. All three were fixed before landing. A final classification pass then moved the AWS container credentials relative URI from the non-secret list to the secret list, because its value is itself a live credential rather than an identifier.

The complete local gate ran spec, lint, and test rungs separately in the foreground on the landed commit: 214 files, 1,744 tests, all 143 conformance cases, and static checks passed. The ratchet moved from 18,817 to 18,874 nonblank lines, matching the ticket's size decision. Hosted runtime run `34860487948` and hosted docs run `34860488140` both passed on commit `44d8dbf`.

Three limits stay open. Pattern-and-value redaction cannot prove a report holds no secret; it only catches a value this run itself supplied under a recognized name. A credential that reaches a provider's report only encoded, truncated, or otherwise transformed passes through unredacted. The registry is Pi's own recognized environment names at the pinned version, so a name Pi adds later is invisible here until the pin moves.
